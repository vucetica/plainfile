# Code of Conduct

## Our pledge

We want Plainfile to be a welcoming project for everyone, whatever their experience level, background, identity or any other personal characteristic. We pledge to act in ways that help build an open, friendly and respectful community.

## Expected behavior

Examples of behavior that helps build a positive environment:

- Showing empathy and kindness toward other people
- Being respectful of opinions, viewpoints and experiences that differ from your own
- Giving constructive feedback, and accepting it gracefully
- Taking responsibility for mistakes and learning from them
- Focusing on what is best for the whole community

## Unacceptable behavior

The following behavior is not welcome in this project:

- Personal attacks, insults or derogatory remarks
- Harassment of any kind, in public or in private
- Publishing someone's private information without their permission
- Repeatedly disrupting discussions, issues or pull requests
- Other conduct that a reasonable person would consider inappropriate in a professional setting

## Enforcement responsibilities

Project maintainers are responsible for explaining the standards of acceptable behavior. They will take fair corrective action in response to any behavior they consider inappropriate.

Maintainers have the right to remove, edit or reject comments, commits, code, issues and other contributions that do not follow this Code of Conduct. When they do, they will explain why.

## Scope

This Code of Conduct applies in all project spaces. These include the GitHub repository (issues, pull requests, discussions and code review) and any other place where someone represents the project, such as an official email address or social media account.

## Reporting

If you experience or witness unacceptable behavior, please report it privately through [GitHub's private reporting form](https://github.com/vucetica/plainfile/security/advisories/new). Only the maintainer can see these reports. For abuse that concerns the GitHub platform itself, you can also use [GitHub's built-in reporting](https://docs.github.com/communities/maintaining-your-safety-on-github/reporting-abuse-or-spam).

Every report will be reviewed promptly and kept confidential. Maintainers must respect the privacy and safety of the person who reports.

## Enforcement

Maintainers will follow these guidelines when they decide what happens after a violation of this Code of Conduct:

1. **Correction.** A private, written warning that explains what the violation was and why it was inappropriate. The maintainer may ask for a public apology.
2. **Warning.** A warning that explains what will happen if the behavior continues. The person may not interact with the people involved for a set period. Breaking these terms can lead to a temporary or permanent ban.
3. **Temporary ban.** A ban from any interaction or public communication with the project for a set period.
4. **Permanent ban.** A permanent ban from any public interaction within the project community.
